# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is
Wikitizer turns a D&D group's exported text-chat logs into structured worldbuilding lore (a free WorldAnvil alternative). The pipeline is: raw chat logs → pure-Python parser → LLM agents that extract structured lore → wiki output.

## Commands
- Activate env: `source venv/bin/activate`
- Run all tests: `pytest` (run from repo root)
- Run one file: `pytest tests/test_speaker_map.py`
- Run one test: `pytest tests/test_speaker_map.py::test_load_speaker_map`
- Build the speaker map from real logs (interactive, one-off): `python scripts/build_speaker_map.py`

## Hard constraints
- **Python 3.9.6.** `dict[str, str]` / `list[X]` builtin generics are fine (PEP 585), but `X | None` union syntax is NOT supported — use `Optional[X]` from `typing`. A 3.10 upgrade is deferred.
- **`logs/` is gitignored and must never be committed.** Files there contain real phone numbers. Keep all chat data local.
- Always pass `encoding="utf-8"` when reading/writing files (names may contain accented chars).
- **The Anthropic API key lives in `.env` (gitignored) as `ANTHROPIC_API_KEY`** and is loaded into the environment by `main.py`'s `load_dotenv()`; the SDK reads it from there. Never read or hardcode the key in source — `agents/base.py` deliberately doesn't (it leaves key-loading to the SDK/entry point). Note the SDK (v0.104) does NOT validate the key at construction; a missing key only surfaces at request time.

## Architecture
Phased build; most of it is still ahead. Current + planned structure:
- `models/` — pydantic v2 data models. `message.py` (`Message`) is parser output; `lore.py` (`Quote`, `Location`, `Character`, `HistoryEvent`, `OtherDetail`) is the LLM-extraction schema. Use `Field(default_factory=list)` for list fields so instances don't share state.
- `speaker_map.py` (top-level) — `load_speaker_map(path) -> dict[str, str]`. Loads `config/speaker_map.json`, a flat map of phone number → name. Phone keys start with `+`; the special `"exporter"` key names whoever exported the chat (their messages have a bare timestamp, no phone prefix). Loader is deliberately minimal — lets `FileNotFoundError`/`JSONDecodeError` bubble up.
- `config/` — data only, no source. Holds `speaker_map.json`.
- `scripts/build_speaker_map.py` — one-off helper (discover phone numbers via regex → prompt for names → save JSON). NOT part of the runtime pipeline. Edit the `files` list inside to point at the real logs.
- `parsers/` — pure Python, no LLM; separate single-responsibility functions. `chat_parser.py` (done, Phase 2.1) turns a log into `list[Message]` via `parse_chat_log(filepath, speaker_map)`: a state machine over two **footer** regexes (the `+phone`/bare-timestamp line *ends* a message and names the sender of the block *above* it — a footer, not a header). `read_clean` reads raw bytes and strips `\r` to dodge the `\r\r\n` double-blank-line trap. Group files attribute the sender by footer phone; the 1-on-1 file has no phones, so it attributes by body left/right alignment. `reaction_filter.py` (done, Phase 2.2) strips export-artifact noise via `filter_reactions(messages) -> list[Message]`: a **pure** function (returns a new list; never mutates the input or its `Message`s — clones changed ones with pydantic v2 `model_copy`) that does NOT parse and does NOT call an LLM. Because `chat_parser` has already merged every multi-line message — including wrapped reactions whose closing quote was stranded on its own line (Pattern 7) — into one `.content`, it checks each content as a **single string** and keys off a fixed opener vocabulary at the *start*, rather than scanning line by line. It drops reaction/tapback pseudo-messages in both English **and** Spanish, across quoted (`Loved “…`), image (`Loved an image`), and emoji (`Reacted 😀 to “…`) forms — matched with **curly** quotes (U+201C), since a straight `"` matches zero reactions (Pattern 10). The opener set was verified exhaustive against all three real logs. Bare `[photo]` tokens are stripped but their captions are kept (captions can be real lore, Pattern 8). URL / link-only filtering is intentionally NOT here — a bare link is human-typed content, not an export artifact, so judging it is deferred to the Phase 3 LLM noise filter.
- `agents/` — LLM layer. `base.py` (done, Phase 3.1) is the shared foundation every specialized agent inherits. `BaseAgent.call_claude(system_prompt, user_message) -> str` makes one Messages API call (defaults: model `claude-sonnet-4-6`, `temperature=0.2`, `max_tokens=4096`) and concatenates the `.text` of every text-type block in the response. `call_claude_json(...)` runs that through `strip_code_fences` then `json.loads`, re-asking up to `max_json_retries` times (default 3) on a `JSONDecodeError` before raising `ClaudeJSONError` (which carries the last raw text); it logs a warning per parse-retry. **Two retry layers, on purpose:** transient HTTP failures are handled by the SDK's own `max_retries=3` (set when `BaseAgent` builds the real `anthropic.Anthropic`), so `call_claude` has NO manual loop; the JSON-parse retry is separate because a 200-response-with-bad-JSON is a different failure the SDK won't retry. The `anthropic` client is **injectable** (`client=`) so tests pass a fake and never hit the network or need a key. `strip_code_fences(text)` is a pure, dependency-free helper that strips a wrapping markdown code fence — a leading three-backtick line (optionally followed by `json`) and the matching trailing three-backtick line — returning text unchanged when there's no clean wrapper (Claude sometimes fences JSON even when told not to). Optional dev cache: **off by default** (constructor `cache=` or env `WIKITIZER_LLM_CACHE`), keyed on a sha256 of `(model, system, user)`, written to gitignored `.llm_cache/`. It lives in `call_claude_json` and caches **only responses that already parsed** — caching pre-validation text would let a cached bad response replay on every retry and defeat the JSON re-ask on re-runs; `call_claude` is intentionally cache-free. `noise_filter.py` (done, Phase 3.2) is the first specialized agent and the only **classifier** (the rest are extractors): `NoiseFilterAgent(BaseAgent).classify(messages) -> list[tuple[Message, str]]` labels every surviving message `lore` / `mechanic` / `noise` / `ambiguous`, paired with its original `Message` in input order — a cheap, high-volume funnel so the expensive extractors only ever see worldbuilding. It classifies only (no extracting/summarizing/rewriting/quoting), which is what lets it run on **Haiku at `temperature=0`** — both overridden via `setdefault` so `client=` injection still works, while `batch_size` (default 50) is a named param kept out of `**kwargs` so it isn't forwarded to `BaseAgent`. It chunks into batches and sends each as a JSON array of **batch-local 0-based integer IDs** (`{"id", "content"}`, `ensure_ascii=False`), asks Claude for `{"id", "label"}` back, and does the rejoin in Python — so Claude refers to messages by number and never echoes their text, and a stray id can't drift across batches. **`ambiguous` is the universal safe fallback:** every failure path — a `ClaudeJSONError` (logged at error, whole batch ambiguous), a non-list response, an unknown/extra id, a junk label, a missing id, or a non-integer id — resolves to `ambiguous`, never `noise`, because a wrongly-dropped `noise` loses lore forever while an `ambiguous` still flows downstream (and surfaces in the Phase 5 review log). One non-obvious validation trap baked into a test: a JSON float (`1.0`) or bool (`false`) id compares equal to and hashes like an int, so it would slip an `in range(n)` check **and** collide with a real id in the `{id: label}` dict — the guard uses `type(...) is int` (not `isinstance`, which would admit `bool`). `select_for_extraction(classified) -> list[Message]` is a pure helper encoding the default-include policy (keep `lore` + `ambiguous`, drop the rest) in one testable place. `classify` is deliberately **sequential**; fanning batches out over threads is the Phase 4 orchestrator's job. `base_extractor.py` (done, Phase 3.3 Step 2) is `BaseExtractor(BaseAgent)`, a **second** shared layer the *extractors* (not the classifier) inherit — so the inheritance is `LocationsExtractor(BaseExtractor)`/`BaseExtractor(BaseAgent)`, NOT extractors off `BaseAgent` directly. It owns the **template-method** spine — `extract(messages) -> list` (empty → `[]`, zero calls; else chunk by `batch_size` and concat `_extract_batch`), `_extract_batch` (build the batch-local `{"id","content"}` payload with `ensure_ascii=False`, call Claude, validate the array, dispatch each entry to `_build_entry`), and `_resolve_quote` — leaving subclasses just a `system_prompt` (class attr) + a `_build_entry(raw, batch)` that shapes one response object into one model; the base's `_build_entry` is a `NotImplementedError` stub. Unlike the noise filter it does **not** override model/temperature — extraction wants careful reasoning, so it keeps `BaseAgent`'s **Sonnet @ `temperature=0.2`** and changes only output size via `kwargs.setdefault("max_tokens", 8192)` (an extractor reply — full entries + verbatim quotes — is far fatter than `{"id","label"}` rows, and a reply cut off mid-JSON fails to parse, retries, gets cut at the same spot, and dies as `ClaudeJSONError`). `batch_size` (default **20, PROVISIONAL** — real value is a later design fork) and `verify_quotes` (default `True`) are named params kept out of `**kwargs`. **Claude never supplies metadata:** each detail cites a message by batch-local `source_id`, and `_resolve_quote` looks the `Message` up to attach `speaker`/`source_file` itself — so a wrong speaker is structurally impossible. `_resolve_quote` guards the id with `type(source_id) is int` (the same float/bool trap the noise filter documents — `isinstance(True, int)` is `True`, so a bool id would index `batch[0/1]` and silently attach the wrong message), bounds-checks it, then runs the verbatim check. **Verbatim-quote verification** (the anti-hallucination core): two pure module-level helpers, `_normalize_for_match` (fold curly quotes/apostrophes U+2018/2019/201C/201D → straight, squeeze all whitespace to single spaces, strip — but **not** lowercased, since case is a real change) and `_quote_is_verbatim` (normalized-quote substring of normalized-message). It absorbs the two near-guaranteed cosmetic mismatches (Claude flattens a multi-line message's newlines; Claude may retype curly punctuation straight) without admitting a genuine reword. One trap baked into a test: an empty/whitespace-only quote normalizes to `""`, a substring of everything, so it's treated as **NOT** verbatim — else a fabricated detail with a blank quote would sail past the guard. The normalizer is deliberately **minimal** (whitespace + curly only); em-dash/ellipsis folding is added only from a real false-alarm in the Phase 5 review log, never speculatively. A failed verbatim check **drops that detail and logs loudly** (the failure you can see beats the one you can't — with `verify_quotes=False` an unverified quote reaches the wiki silently). Error philosophy mirrors the noise filter, minus the universal `ambiguous` bucket: never crash, contain failures, log at three levels — a bad **batch** → `[]` + `error`, a bad **entry** → skipped + `warning`, a bad **detail** → dropped + `warning`. `noise_filter.py` and the extractors share nothing but `BaseAgent`'s plumbing; **no entity/alias merging** happens here even within a batch (a location returned twice is emitted twice — reconciling is Phase 4.1), and identical quotes are deduped within a single entry while its `details` are kept 1:1. `locations_extractor.py` (done, Phase 3.3 Step 1) is `LocationsExtractor(BaseExtractor)`, the first extractor: `extract(messages) -> list[Location]`, supplying only the locations `SYSTEM_PROMPT` and a `_build_entry` that pulls `name` (skip if not a non-empty str), defensive `aliases` (string-only, and only if a list), and detail/quote/`source_id` triples into a validated `Location` (catching `ValidationError`). The remaining extractors (characters/history/other, 3.4–3.5) are still planned and will inherit `BaseExtractor`.
- `main.py` (top-level) — pipeline entry point. Right now its one real job is to call `load_dotenv()` so the Anthropic SDK can read `ANTHROPIC_API_KEY` from the environment (a `.env` file is NOT auto-loaded, and key-loading belongs here, not in `base.py`). The parse → filter → agents → wiki wiring fills in over later phases.

## Chat log format
Each message ends with a **footer** line — either `+16303463392 MM/DD/YYYY HH:MM:SS` (phone-prefixed sender) or a bare `MM/DD/YYYY HH:MM:SS` (the exporter) — and the phone names the message *above* it (footer, not header). The parser maps the phone through the speaker map; no phone → exporter; an unknown phone falls back to the raw number + a logged warning. The 1-on-1 log has no phone numbers at all, so there the sender is read from body left/right alignment instead. Real exports are truncated mid-message (final footer cut off); the parser recovers that last message rather than dropping it. Full quirk catalogue in `FORMAT_NOTES.md`.

## Testing conventions
Use pytest's `tmp_path` fixture to write throwaway config/log files rather than touching real ones. Test that bad input raises the right error with `pytest.raises(...)`.
