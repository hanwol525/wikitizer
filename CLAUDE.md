# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is
Wikitizer turns a D&D group's exported text-chat logs into structured worldbuilding lore (a free WorldAnvil alternative). The pipeline is: raw chat logs → pure-Python parser → LLM agents that extract structured lore → wiki output.

## Commands
- Activate env: `source venv/bin/activate`
- Run the pipeline: `python main.py --files logs/*.txt`
- ...with a restricted copy for players (a source file's secrets hidden): `python main.py --files logs/*.txt --exclude-sources dm.txt`
- ...with a present-day year so the timeline can resolve relative dates ("200 years ago"): `python main.py --files logs/*.txt --current-year 1424`
- ...pointing at non-default config: `python main.py --files logs/*.txt --speaker-map config/speaker_map.imessage.json --player-map config/player_map.json`
- ...without a declared party (opt-out; PCs may duplicate/mis-attribute): `python main.py --files logs/*.txt --no-player-map`
- After a run, save who-plays-whom for next time: add `--confirm-players`. Reuse cached LLM responses while debugging the same logs: add `--cache`.
- **A declared party (`config/player_map.json`) is REQUIRED** — the run hard-stops before any paid call without it, unless `--no-player-map` is passed.
- Run all tests: `pytest` (run from repo root) — the fast, mocked suite; now **excludes** anything marked `integration` (via `addopts = -m "not integration"` in `pytest.ini`).
- Run the live extractor tests: `pytest -m integration` (makes real Anthropic API calls; needs `ANTHROPIC_API_KEY`). Opt-in only.
- Run one file: `pytest tests/test_speaker_map.py`
- Run one test: `pytest tests/test_speaker_map.py::test_load_speaker_map`
- Build the config (interactive, one-off, in order): `python scripts/build_imessage_speaker_map.py logs/*.txt -o config/speaker_map.json` then `python scripts/build_player_map.py`

## Hard constraints
- **Python 3.9.6.** `dict[str, str]` / `list[X]` builtin generics are fine (PEP 585), but `X | None` union syntax is NOT supported — use `Optional[X]` from `typing`. A 3.10 upgrade is deferred.
- **`logs/` is gitignored and must never be committed.** Files there contain real phone numbers. Keep all chat data local.
- Always pass `encoding="utf-8"` when reading/writing files (names may contain accented chars).
- **The Anthropic API key lives in `.env` (gitignored) as `ANTHROPIC_API_KEY`** and is loaded into the environment by `main.py`'s `load_dotenv()`; the SDK reads it from there. Never read or hardcode the key in source — `agents/base.py` deliberately doesn't (it leaves key-loading to the SDK/entry point). Note the SDK (v0.104) does NOT validate the key at construction; a missing key only surfaces at request time.

## Architecture
Phased build; most of it is still ahead. Current + planned structure:
- `models/` — pydantic v2 data models. `message.py` (`Message`) is parser output; `lore.py` (`Quote`, `Detail`, `Alias`, `Location`, `Character`, `HistoryEvent`, `Organization`, `Item`, `PeopleAndCultures`, plus the `Scope` `(str, Enum)` for `HistoryEvent.scope`) is the LLM-extraction schema. Use `Field(default_factory=list)` for list fields so instances don't share state. **`details` on the five detail-carrying entities is `list[Detail]` (was `list[str]`, Phase 4.6 Part 1):** a `Detail` is `text` + a `source_files` list — the fact-grain twin of `Quote` — and each extractor tags every fact with the `source_file` of the message it cited, for free at build time (the quote is already resolved right there; the three name-from-first-detail fallbacks read `details_out[0].text`, not the object). This is **provenance consumed by the `--exclude-sources` restricted view** (`exclusion.filter_entities`, Part 2): nothing renders it in the FULL doc (the renderer reads only `Detail.text`) and the reconciler **hides it from the merge prompt** (see the reconciler entry), so it is **byte-for-byte invisible** in the full wiki and merge prompt (the carve happens only in the second, restricted doc). `source_files` is a **list**, not a scalar, because the reconciler unions the sources of one fact stated in more than one file (so a later exclusion drops it only when *all* its sources are excluded). **Phase 4.6 Part 3 gave names/aliases provenance too:** a new **`Alias`** model (`text` + `source_files`, the name-grain twin of `Detail`) replaces the bare `aliases: list[str]` on all six types (`aliases` is now `list[Alias]`), and each type carries a **`name_sources: list[str]`** side field declared right after `name` (which keeps `_entity_for_prompt`'s JSON key order stable; dormant on `HistoryEvent`, carried so all six share one shape). Both are tagged at extraction from the **file-pure batch** (`batch[0].source_file`), which is what lets the `--exclude-sources` carve strip secret aliases and **re-head** a secret canonical name — closing the entity-name leak an earlier review found (see the reconciler + orchestrator entries). `Scope` is `world`/`regional`/`personal`; the `(str, Enum)` mix-in (3.9's stand-in for 3.11's `StrEnum`) makes `Scope.WORLD == "world"` true so it JSON-serializes cleanly and renderer `== "world"` checks keep working, while the Enum makes pydantic **reject** any off-menu value. **Phase C (the prose pass) added a `prose: Optional[str]` field to ALL six entity types** — the copyedited body the renderer prefers over the joined `details` — and **`Character` gained `pronouns: list[str]`** (declared pronouns from the party config; they shape pronoun USAGE in authored details + prose but are never rendered as a label), alongside its `is_pc` + `player_name`. All six entity models — `Location`/`Character`/`HistoryEvent`/`Organization`/`Item`/`PeopleAndCultures` — carry a `name` + `aliases` so the Phase 4.1 reconciler can match them all the same way. The three typed categories `Organization`/`Item`/`PeopleAndCultures` are **exact `Location` clones** (same four fields) that replaced the retired `OtherDetail` catch-all; the per-category inclusion discipline lives in each one's extractor prompt (separate later phases), not in the schema, and the "tie" of a nameless Org/Item (e.g. "an agency in Crown's Nest", "CJ's amulet") stays in the prose `details` for the cross-link pass, never a `tied_to` field. `reconcile.py` (done, Phase 4.1a) holds the **decision-object contract** the reconciler LLM hands back — `ReconcileDecision` (`merges` + `possible_duplicates`, both `default_factory=list`), `MergeGroup` (`members` = 0-based **indices** into the input list, a `canonical` heading, and a usually-empty `conflicts`), `PossibleDuplicate` (a suspicious-but-unmerged pair + `note`), and `DetailConflict` (carries each side's **detail text + source**, NOT a `detail #N` coordinate, because the stored detail/quote lists keep no clean index-to-index mapping). One model set covers all six entity types — a decision is just indices + names, never a type-specific field — and anything not named in `merges` is an **implicit singleton** (the LLM never echoes unique entries, so the common case is cheap and a forgotten entry just stays its own page, the harmless under-merge direction).
- `speaker_map.py` (top-level) — `load_speaker_map(path) -> dict[str, str]`. Loads `config/speaker_map.json`, a flat map of **contact name or phone handle → canonical name**. The committed map is **name-keyed** — imessage-exporter resolves contacts to display names, so the keys are names (`{"Matt Fabian": "Matt", ..., "exporter": "Hannah"}`), NOT `+`-phone numbers; a raw phone handle still works as a key (matched via E.164 normalization). The parser's `_resolve_sender` tries a **direct key hit first, then phone normalization**. The special `"exporter"` key names whoever exported the chat (their messages show as `Me`). Loader is deliberately minimal — lets `FileNotFoundError`/`JSONDecodeError` bubble up.
- `text_norm.py` (top-level) — **shared canonical name-folding**, used by BOTH the anchor layer (`renderer/crosslink.slugify`) and the merge layer (`agents/reconciler`'s name-key). `slug(name)` → the anchor id / merge slug (NFKD ASCII-fold, lowercase, spaces→hyphens, keep internal hyphens, strip apostrophes + other non-`[a-z0-9-]`, collapse+trim; `""` for an all-punctuation name); `name_key(name)` is literally `slug` with hyphens→spaces (so a downstream article-strip + token split still operate on words). The load-bearing invariant: **`slug(a) == slug(b)` ⟹ `name_key(a) == name_key(b)`** — the merge key is defined in terms of the slug precisely so two names that become the same anchor always land in the same merge bucket. This closed a real bug: `slugify` stripped apostrophes/accents but the old reconciler key kept them, so "Scoia'tael" split into several merge buckets yet collapsed to ONE anchor (duplicate pages + dead links). Pure, no I/O, no logging.
- `player_map.py` (top-level) — the **declared-party loader** (distinct from `config/player_map.json`, the data). Who plays which character is ground truth only the group knows (no heuristic recovers it reliably), so it's user config, gitignored like the speaker map. Canonical shape is a **list** of `{player, main_name, last_name?, aliases?, pronouns?}` entries; `DeclaredCharacter` is the fully-normalized form, and **recognition** matches on the cross-product `{main_name ∪ aliases} × {"", last_name}` (so "Kriggy"/"Krigius"/"Kriggy Krieger"/"Krigius Krieger" all fold, but a bare last name never does). `declared_characters` parses ANY supported shape (incl. three back-compat dict forms) into `list[DeclaredCharacter]`; `build_character_lookup` → `{recognition_name_lower: player}` and `build_pronoun_lookup` → `{recognition_name_lower: pronouns}` feed the characters extractor, while `declared_groups`/`declared_groups_with_players` feed the reconciler's declared-merge floor. `load_player_map` is **tolerant of a missing file (→ `[]`) but STRICT on a parsed-but-wrong shape** (validated via `declared_characters`), so a broken config fails before any paid call rather than silently disabling the party. Pronouns default to `["they","them"]`.
- `config/` — data only, no source. Holds `speaker_map.json` and `crosslink_words.json` (the optional cross-link common-word config `{"require_article": [], "never_link": []}`; the orchestrator loads it via `load_crosslink_words` and threads it into `render_wiki`, both lists defaulting empty so a fresh clone with no file runs clean).
- `scripts/build_imessage_speaker_map.py` — one-off interactive helper: discover sender names in the imessage-exporter exports → prompt for canonical names → save the NAME-keyed map `{contact-name: name, "exporter": you}` (default output `config/speaker_map.imessage.json`; then run with `--speaker-map config/speaker_map.imessage.json`, or pass `-o config/speaker_map.json` to write the runtime default). `scripts/build_player_map.py` — the REQUIRED step-1 party builder: reads the speaker map → prompts per person for their character(s) (main_name, last_name, aliases, pronouns; multi-PC; non-players skippable) → saves the list-form `config/player_map.json`. Both use injectable `input_fn`/`print_fn` (testable without stdin). NOT part of the runtime pipeline.
- `parsers/` — pure Python, no LLM. `imessage_export_parser.py` turns an imessage-exporter TXT export into `list[Message]` via `parse_imessage_export(filepath, speaker_map)`: a **two-line-handshake** state machine (a timestamp line whose next line is a plausible sender opens a message; its body runs to the next such boundary), with `read_clean` (raw-bytes UTF-8 read stripping `\r` to dodge the `\r\r\n` double-blank trap) and **structural** stripping of reactions (`Tapbacks:`), attachment paths, read receipts, and group announcements (`_strip_annotations`) — so there is nothing reaction-shaped left to post-filter (the old `reaction_filter.py` was removed with the legacy parser). `ingest.py` is the thin entry point the orchestrator calls: `parse_messages(filepath, speaker_map)` delegates to `parse_imessage_export` (a seam kept so a future format could be re-added behind one call site). URL / link-only filtering is intentionally NOT here — a bare link is human-typed content, so judging it is deferred to the Phase 3 LLM noise filter.
- `agents/` — LLM layer. **`llm_client.py` is the pluggable backend beneath every agent (NOT in earlier docs):** the whole app talks to the model through one method (`BaseAgent.call_claude` → `client.messages.create(...)`), so to run a role on a cheaper model without rewriting that method, `AnthropicCompatClient` presents the same tiny Anthropic surface (`.messages.create(...) → .content[].text`) over an **OpenAI-compatible** client (OpenRouter/GLM/Fireworks), translating to Chat Completions below it. Backend is chosen **per role** by env `WIKITIZER_<ROLE>_MODEL` (roles `NOISE`/`EXTRACT`/`RECONCILE`/`PROSE`): a value prefixed `openrouter:`/`openai:` routes to the OpenAI-compat endpoint (`LLM_OPENAI_BASE_URL`/`LLM_OPENAI_API_KEY`) with the bare slug, no prefix → Anthropic, unset → the `DEFAULT_MODELS` per-role defaults (**Haiku** for NOISE, **Sonnet** for EXTRACT + PROSE, **Opus `claude-opus-4-8`** for RECONCILE). `LLMBackendResolver.resolve(role) → (client, model)` caches one client per provider; an `override_client` (a test fake, or the orchestrator's injected client) short-circuits selection for EVERY role. Robustness extras: `_extract_text` reads `content`, then falls back to `reasoning_content`/`reasoning` (GLM reasoning models leave the answer there) and logs `finish_reason` when still empty (so a `length` truncation is visible, not a silent empty-string retry storm); `WIKITIZER_OPENAI_REASONING` (off / low|medium|high / raw-JSON) disables or caps a reasoning model's thinking on the OpenAI-compat path only; `WIKITIZER_LLM_TIMEOUT` (default 300s) bounds a stalled request. SDKs are imported lazily, so an Anthropic-only user never needs `openai` installed (both `anthropic==0.104.1` and `openai==2.45.0` are pinned). `base.py` (done, Phase 3.1) is the shared foundation every specialized agent inherits. `BaseAgent.call_claude(system_prompt, user_message) -> str` makes one Messages API call (defaults: model `claude-sonnet-4-6`, `temperature=0.2`, `max_tokens=4096`) and concatenates the `.text` of every text-type block in the response. `call_claude_json(...)` runs that through **`loads_tolerant`** (strict `json.loads(strip_code_fences(...))` first, then a **`json_repair==0.44.1`** fallback that peels a conversational preamble AND re-escapes the stray straightened quotes Claude leaves inside verbatim strings), re-asking up to `max_json_retries` times (default 3) on a `JSONDecodeError` before raising `ClaudeJSONError` (which carries the last raw text); it logs a warning per parse-retry. **Two retry layers, on purpose:** transient HTTP failures are handled by the SDK's own `max_retries=3` (set inside `build_llm_client`, which builds `BaseAgent`'s default client — see the `llm_client.py` note above), so `call_claude` has NO manual loop; the JSON-parse retry is separate because a 200-response-with-bad-JSON is a different failure the SDK won't retry. The `anthropic` client is **injectable** (`client=`) so tests pass a fake and never hit the network or need a key. `strip_code_fences(text)` is a pure, dependency-free helper that strips a wrapping markdown code fence — a leading three-backtick line (optionally followed by `json`) and the matching trailing three-backtick line — returning text unchanged when there's no clean wrapper (Claude sometimes fences JSON even when told not to). Optional dev cache: **off by default** (constructor `cache=` or env `WIKITIZER_LLM_CACHE`), keyed on a sha256 of `(model, system, user)`, written to gitignored `.llm_cache/`. It lives in `call_claude_json` and caches **only responses that already parsed** — caching pre-validation text would let a cached bad response replay on every retry and defeat the JSON re-ask on re-runs; `call_claude` is intentionally free of THAT dev cache, but it DOES wrap the system prompt in a single `cache_control: {"type": "ephemeral"}` block so Anthropic **prompt-caches** the byte-stable system prefix — a run's many batch calls bill it once (+write) and read it back at ~0.1x (a prefix under the model minimum silently no-ops; wholly separate from the dev disk cache). `noise_filter.py` (done, Phase 3.2) is the first specialized agent and the only **classifier** (the rest are extractors): `NoiseFilterAgent(BaseAgent).classify(messages) -> list[tuple[Message, str]]` labels every surviving message `lore` / `mechanic` / `noise` / `ambiguous`, paired with its original `Message` in input order — a cheap, high-volume funnel so the expensive extractors only ever see worldbuilding. It classifies only (no extracting/summarizing/rewriting/quoting), which is what lets it run on **Haiku at `temperature=0`** — both overridden via `setdefault` so `client=` injection still works, while `batch_size` (default 50) is a named param kept out of `**kwargs` so it isn't forwarded to `BaseAgent`. It chunks into batches and sends each as a JSON array of **batch-local 0-based integer IDs** (`{"id", "content"}`, `ensure_ascii=False`), asks Claude for `{"id", "label"}` back, and does the rejoin in Python — so Claude refers to messages by number and never echoes their text, and a stray id can't drift across batches. **`ambiguous` is the universal safe fallback:** every failure path — a `ClaudeJSONError` (logged at error, whole batch ambiguous), a non-list response, an unknown/extra id, a junk label, a missing id, or a non-integer id — resolves to `ambiguous`, never `noise`, because a wrongly-dropped `noise` loses lore forever while an `ambiguous` still flows downstream (and surfaces in the Phase 5 review log). One non-obvious validation trap baked into a test: a JSON float (`1.0`) or bool (`false`) id compares equal to and hashes like an int, so it would slip an `in range(n)` check **and** collide with a real id in the `{id: label}` dict — the guard uses `type(...) is int` (not `isinstance`, which would admit `bool`). `select_for_extraction(classified) -> list[Message]` is a pure helper encoding the default-include policy (keep `lore` + `ambiguous`, drop the rest) in one testable place. `classify` **fans its batches out over a `ThreadPoolExecutor`** when built with `max_workers>1` (the orchestrator passes `config.max_workers`); it still returns labels in input order. (Earlier docs called it deliberately sequential — that parallelism moved inward.) `base_extractor.py` (done, Phase 3.3 Step 2) is `BaseExtractor(BaseAgent)`, a **second** shared layer the *extractors* (not the classifier) inherit — so the inheritance is `LocationsExtractor(BaseExtractor)`/`BaseExtractor(BaseAgent)`, NOT extractors off `BaseAgent` directly. It owns the **template-method** spine — `extract(messages) -> list` (empty → `[]`, zero calls; else **group messages by `source_file` first, then** chunk each file by `batch_size` and concat `_extract_batch` — **file-pure batches (Phase 4.6 Part 3)**, so no batch ever mixes two files: load-bearing because `_quote_is_verbatim` proves a QUOTE came from its message but a detail's TEXT is unchecked free-form prose, so a mixed batch would let Claude weave file B's secret into a fact cited to file A's public quote and silently defeat `--exclude-sources`; it also lets `_build_entry` trust `batch[0].source_file` as the file for the whole batch), `_extract_batch` (build the batch-local `{"id","content"}` payload with `ensure_ascii=False`, call Claude, validate the array, dispatch each entry to `_build_entry`), and `_resolve_quote` — leaving subclasses just a `system_prompt` (class attr) + a `_build_entry(raw, batch)` that shapes one response object into one model; the base's `_build_entry` is a `NotImplementedError` stub. Unlike the noise filter it does **not** override model/temperature — extraction wants careful reasoning, so it keeps `BaseAgent`'s **Sonnet @ `temperature=0.2`** and changes only output size via `kwargs.setdefault("max_tokens", 8192)` (an extractor reply — full entries + verbatim quotes — is far fatter than `{"id","label"}` rows, and a reply cut off mid-JSON fails to parse, retries, gets cut at the same spot, and dies as `ClaudeJSONError`). `batch_size` (default **20, PROVISIONAL** — real value is a later design fork) and `verify_quotes` (default `True`) are named params kept out of `**kwargs`. **Claude never supplies metadata:** each detail cites a message by batch-local `source_id`, and `_resolve_quote` looks the `Message` up to attach `speaker`/`source_file` itself — so a wrong speaker is structurally impossible. `_resolve_quote` guards the id with `type(source_id) is int` (the same float/bool trap the noise filter documents — `isinstance(True, int)` is `True`, so a bool id would index `batch[0/1]` and silently attach the wrong message), bounds-checks it, then runs the verbatim check. **Verbatim-quote verification** (the anti-hallucination core): two pure module-level helpers, `_normalize_for_match` (fold curly quotes/apostrophes U+2018/2019/201C/201D → straight, squeeze all whitespace to single spaces, strip — but **not** lowercased, since case is a real change) and `_quote_is_verbatim` (normalized-quote substring of normalized-message). It absorbs the two near-guaranteed cosmetic mismatches (Claude flattens a multi-line message's newlines; Claude may retype curly punctuation straight) without admitting a genuine reword. One trap baked into a test: an empty/whitespace-only quote normalizes to `""`, a substring of everything, so it's treated as **NOT** verbatim — else a fabricated detail with a blank quote would sail past the guard. The normalizer is deliberately **minimal** but now folds **curly quotes/apostrophes, the ellipsis, and en/em-dashes** (`_SMART_PUNCT`) plus a **hyphen-run collapse** (`-{2,}` → `-`, so `-`/`--`/`—` all compare equal) — each earned from a real false-alarm in the review log, never speculatively; it is still NOT lowercased (case is a real change). A failed verbatim check **drops that detail and logs loudly** (the failure you can see beats the one you can't — with `verify_quotes=False` an unverified quote reaches the wiki silently). Error philosophy mirrors the noise filter, minus the universal `ambiguous` bucket: never crash, contain failures, log at three levels — a bad **batch** → `[]` + `error`, a bad **entry** → skipped + `warning`, a bad **detail** → dropped + `warning`. `noise_filter.py` and the extractors share nothing but `BaseAgent`'s plumbing; **no entity/alias merging** happens here even within a batch (a location returned twice is emitted twice — reconciling is Phase 4.1), and identical quotes are deduped within a single entry while its `details` are kept 1:1. `locations_extractor.py` (done, Phase 3.3 Step 1) is `LocationsExtractor(BaseExtractor)`, the first extractor: `extract(messages) -> list[Location]`, supplying only the locations `SYSTEM_PROMPT` and a `_build_entry` that pulls `name` (skip if not a non-empty str), defensive `aliases` (string-only, and only if a list), and detail/quote/`source_id` triples into a validated `Location` (catching `ValidationError`). `characters_extractor.py` (done, Phase 3.4) is `CharactersExtractor(BaseExtractor)`, the second extractor: `extract(messages) -> list[Character]` (inherited unchanged), supplying a roster-aware system prompt and a `_build_entry` whose detail/quote loop mirrors the locations one and adds three character-specific fields. Its whole reason for existing beyond "locations with more fields" is the **player/character conflation trap**: the chat mixes the real human "Sam, you free Thursday?" with the character "Sam plays Kriggy", and we must not mint a character named after a real person out of table talk. Two layers guard it, **neither baking real names into committed source** (the repo is public): (1) the **roster threads in at runtime** — `__init__` takes a **required** `player_names` (the real names, which the orchestrator sources from the speaker map's *values*; the extractor itself does no file I/O) and fills a literal `__PLAYER_ROSTER__` placeholder in the prompt via **`.replace()`, NOT `.format()`/f-string** (the prompt is full of literal `{ }` in its JSON example and `.format()` would treat each brace as a fill-in slot), `sorted()` for a byte-stable prompt so caching can kick in later; `system_prompt` is set as an **instance attribute** (quietly takes precedence over the class attr `LocationsExtractor` uses — zero `BaseExtractor` changes), and a lowercased `_roster_lookup` set powers the checks (blank/whitespace names are filtered out first, so an effectively-empty roster *disables* the check instead of building a truthy `{""}` that would null every `player_name`). (2) A **Python-side roster check**: `is_pc` (non-bool → `False`, the NPC default), `player_name` (`Optional`, validated against the roster **case-insensitively** and nulled-with-a-warning if it isn't a known real person — but an **empty roster disables the check**, and it **validates without rewriting**, so a matched `"sam"` stays `"sam"`), and a **name-collision flag** (a character whose `name` matches a real person is **KEPT but logged**, never dropped — a coincidence/in-joke is legitimate, and this log is the safety net that makes the softened prompt safe, catching the one mix-up the `player_name` check can't: a real-name character *with* that same `player_name`). **(3) Authoritative stamping from the declared party (`player_map`, OPTIONAL):** the extractor also takes the user's `config/player_map.json` (threaded from the orchestrator). When a character's `name` OR any alias matches a declared character (`build_character_lookup`, normalized strip+lower), its `player_name` is **stamped from the map and `is_pc` forced `True`**, OVERRIDING the LLM — who plays whom is ground truth only the group knows. When a `player_map` IS configured but the character is UNDECLARED, the LLM's `player_name` guess is instead **dropped** (a stray narrator name there would fabricate a `player_name` clash that vetoes a legitimate merge downstream); with NO `player_map` (the synthetic/offline path) the legacy roster-validated guess stands. It also stamps declared **`pronouns`** (`build_pronoun_lookup`) onto the `Character` and threads a `__DECLARED_PRONOUNS__` guide into the prompt so authored details use the right pronouns. The model change this phase: `Character` gained an `aliases` field mirroring `Location`'s **exactly** (same name, `Field(default_factory=list)`) so the reconciler/renderer can walk both types the same way. The prompt also scopes a **character to a single individual** (one person or one creature): a whole people/race/species/culture taken as a group is NOT a character but the separate `PeopleAndCultures` lore type, so a creature-*kind* (e.g. "direwolves") isn't double-listed under both Characters and People & Cultures — the reconciler dedups only *within* a type, never across them, so this boundary has to live in the prompt. The prompt also captures a **named individual even in a historical/legendary/past-tense context** (a famous long-dead figure like the "Wizard Strong" is still a character), kept strictly scoped to individuals so families/houses/clans/dynasties and whole peoples never leak in as characters. **Scope guards, all parked for later:** no `input()`/interactive confirmation (the player→character review step lives in the orchestrator *after* the Phase 4.1 reconciler), the collision flag is a **log line only** (no `needs_review` field on the model), no entity/alias merging (reconciler 4.1), no DM-specific handling. (The `is_pc`/`player_name` authoritative stamping from the declared party is now DONE — see (3) above — so the old "validates without rewriting / no cross-check" caveat holds only on the no-`player_map` path; the player→character *review* remains the orchestrator's `--confirm-players` step.) `history_extractor.py` (done, Phase 3.5) is `HistoryExtractor(BaseExtractor)`, the **third and final** extractor: `extract(messages) -> list[HistoryEvent]` (inherited), with no `__init__` (it injects nothing — unlike Characters), just a class-attr `system_prompt` and a `_build_entry`. It is **structurally different** from the other two: a `HistoryEvent` has **no `details` list** — it's one prose `description` backed by a **flat** `supporting_quotes` list — so `_build_entry` does NOT copy the Location/Character detail loop; it loops a flat `quotes` list (each entry just `quote` + `source_id`, no per-detail text, because the description IS the single summary). **Order matters** in `_build_entry`: `description` is validated **first** (the *only* drop-the-event case — an event with no description is a label pointing at nothing) because the `name` fallback derives from it; a missing/blank `name` does NOT drop the event but falls back to a trimmed first-sentence of the description (`description.strip().split(".")[0][:80]`), since the description is real lore and losing it over a missing *label* would be silly. **`scope` coercion** is the other new piece: because `HistoryEvent.scope` is now the strict `Scope` Enum (which *rejects* off-menu values and would make the `except ValidationError` drop the whole event), the extractor **coerces the raw scope before the model sees it** — `.strip().lower()` (so `"World"`/`" world "` pass without defaulting), and anything not in `VALID_SCOPES` (derived `{s.value for s in Scope}`, so the list can't drift) defaults to **`"world"` and logs** — `"world"` not the narrowest bucket on purpose, because a misfiled event only gets re-filed if it's *visible* in the loud front-of-wiki bucket rather than hidden in `personal`. The coercion stays **minimal** (three values + default, no fuzzy synonym mapping). **Empty-quotes is kept-but-flagged, not dropped:** if every quote fails the verbatim check, the event is still emitted (missing lore is the worse sin) but logged loudly — more sensitive than the other two because a Location's *name* is a real chat mention while a history event's name is **model-generated**, so a zero-quote event has nothing anchoring it to the log. **`chronological_position` is deliberately never set by the extractor** (and never asked of Claude — ordering info is preserved *inside the `description` sentence* instead): assigning a real global ordering needs a pass that sees every event at once, so the field stays on the model as a **mailbox** the later timeline pass fills and the renderer (4.4) reads. **`date_text` (`Optional[str] = None`, done):** the in-world date **exactly as the campaign stated it** ("342 AR", "the Third Age"), or `None` when none is stated — promoted out of the description prose into a first-class field so the renderer can show a clean date prefix and the **4.1b timeline pass** can find it reliably no matter how the sentence was phrased. The extractor **captures it verbatim** (step 4b: `.strip()` only — no parsing, normalizing, or number-conversion; a non-string/blank value defaults to `None`), and a **relative clue** ("before the Empire fell") is **not** a date — it stays in the description with `date_text` null. Crucially it is **not** `chronological_position` (the prompt still forbids any position number); capturing a stated date and *ordering* events stay separate jobs. Backward-compatible: a dateless campaign (like the original logs) gets `date_text=None` throughout and the pipeline is unchanged. **`calendar_system` (`Optional[str] = None`, Fork B):** which calendar system an event's date is in ("AR years", "Elder Scrolls eras"). Like `chronological_position` (and *unlike* `date_text`), the **extractor never sets it** — the **4.1b timeline pass derives it**, because assigning a *consistent* system label across events (and recognizing that two different notations like "1347" / "Third Era 347" are the same system) needs the whole-timeline view a per-batch extractor can't have. It enables **Fork B**: the renderer (4.4) groups events into one ordered timeline **per calendar system**, so a campaign running multiple dating systems gets a faithful separate timeline for each. The 4.1a reconciler leaves it `None` at merge time (a 4.1b field, so `_combine_group`'s History branch passes `calendar_system=None` for symmetry next to `chronological_position=None`); a single-system/dateless campaign gets `None` throughout — fully backward-compatible. **Scope guards (parked):** no timeline/position building, no entity merging or ordering even within a batch, minimal scope coercion. `organization_extractor.py` (done) is `OrganizationExtractor(BaseExtractor)`, the first of the three **typed-lore** extractors that replace the retired `OtherDetail` catch-all: `extract(messages) -> list[Organization]` (inherited), no `__init__`, just a class-attr `system_prompt` + a `_build_entry`. Its **inclusion gate is wider than "has a proper name":** an organization qualifies if it's named OR if it's unnamed but clearly **tied** to a specific location/character/event ("the council that rules Gol"), in which case Claude synthesizes a short descriptive label as the `name`. A **proper name alone is sufficient even with no other detail stated** — a name-only org is captured (carrying the name itself as its single supporting quote), and a bare comma-separated list of named groups (e.g. sports teams) yields one org per name; only a vague group with **neither** a name **nor** a tie ("some merchants") is dropped. The **Location↔Organization split** is the load-bearing boundary: a realm like the Krieger Imperium is a PLACE in the locations extractor (territory/geography) and the governing BODY here (who rules it, how it's structured) — the same realm legitimately appears in **both**, and this extractor captures only the group/governance side (a lone individual is a Character; a whole people/culture is the future PeopleAndCultures extractor). Its `_build_entry` mirrors `LocationsExtractor`'s detail loop but processes **details before the name**, because a missing name falls back to a short form (`[:80]`) of the first surviving detail (the **History-style keep-don't-drop** move) — and it drops the entity only when it has *neither* a usable name *nor* any surviving detail. `item_extractor.py` (done) is `ItemExtractor(BaseExtractor)`, the second typed-lore extractor: `extract(messages) -> list[Item]` (inherited), no `__init__`, the **same shape as `OrganizationExtractor`** — the wider named-OR-tied inclusion gate (with a synthesized short label for a tied-but-unnamed object) and the details-before-name `[:80]` fallback in `_build_entry`. Its bar: an **item** is a physical object you could in principle pick up or carry (a named or tied weapon, armor, artifact, relic, or treasure); ordinary loot merely being bought/sold/counted ("a regular dagger and some rope") is skipped, and a place/person/organization/people is some other extractor's job. `people_and_cultures_extractor.py` (done) is `PeopleAndCulturesExtractor(BaseExtractor)`, the third typed-lore extractor: `extract(messages) -> list[PeopleAndCultures]` (inherited), no `__init__`, the same `_build_entry` shape (details-before-name `[:80]` fallback). It captures a **collective group defined by shared identity** — a race, species, ethnic group, tribe/clan, a nation's people, or a culture ("the Krieg", "direwolves" as a kind). Unlike Organizations/Items it has **no inclusion gate**: any named or clearly-described distinct group counts (no proper name or tie required; a short label is synthesized if unnamed). Two easy-to-confuse boundaries keep it distinct: a single **individual** is a Character ("Kriggy"; one named direwolf in a fight), and a formal, structured **body** is an Organization ("the Krieger Imperium", their state) — the people themselves ("the Krieg") belong here. (This pairs with a one-line clarification to the **characters** prompt so a creature-kind isn't double-counted as a character; both must be in place before a real end-to-end run.) With Locations/Characters/History plus the three typed categories (Organizations/Items/People & Cultures) all done, the extractor layer is complete; the next consumer of all extractor output is the Phase 4.1 reconciler, which merges duplicate entities and unifies aliases across the whole run. **All six extractor prompts apply an explicit precision bar:** skip one-off/joke/unnamed-descriptive mentions, don't coin a name the text didn't give, and use the fullest proper form as the canonical `name` (nicknames/titles → aliases); cross-entity **merging** remains the reconciler's job. `reconciler.py` (done, Phase 4.1a) is `Reconciler(BaseAgent)` — it inherits `BaseAgent` **directly**, like the noise filter and **not** `BaseExtractor`, because it shares none of the extractor spine: it **does NOT batch** (de-dup is global *within* a type — a duplicate split across two batches is invisible, so the whole one-type list goes in a **single** call; fine at our scale of tens-of-entries-per-type) and it **introduces no new quotes** (nothing to verbatim-verify — quotes ride along **by reference** in pure Python). It uses **Opus** (`DEFAULT_RECONCILE_MODEL = claude-opus-4-8`, the `RECONCILE` role in `llm_client.DEFAULT_MODELS`) — the pipeline's hardest JUDGMENT work (deciding what is the same entity, one shot over the whole list) at only ~9 calls/run, so it earns the strongest model; the extractors stay Sonnet, the classifier Haiku. The public method `reconcile(entries) -> list` takes one entity type and returns that same type; the orchestrator (later phase) calls it **once per type**, and it de-dups **within a type only** — cross-type separation (keeping "Direwolves" out of both Characters *and* People & Cultures) is already the extractor prompts' job. **The load-bearing split is LLM-decides / Python-assembles:** the LLM only emits a `ReconcileDecision` (which entries merge, the `canonical` name, which details conflict, which pairs are suspicious) and a **pure-Python combiner** (`_combine_group`) does the actual fact-merging straight from the *original* objects — unioning aliases (every losing `name` becomes an alias; canonical never aliases itself), concatenating `details` (now `Detail` objects, Phase 4.6 Part 1) with **`_dedup_details`** — which collapses same-`text` facts (a light `.strip()` key so a subtly-different fact is never eaten, first-seen text kept **verbatim**, order preserved, so the rendered wiki is byte-identical) and **unions** their `source_files` (a fact stated in two files remembers both, so a future `--exclude-sources` strips it only when *all* its sources go); plain `_dedup_preserve_order` still de-dupes aliases/descriptions and runs *inside* `_dedup_details`. **The `source_files` tags are hidden from the merge prompt:** `_entity_for_prompt` reduces each entity's details back to bare text strings before serialising, so the JSON Claude sees is **byte-identical** to before the tags existed — merge decisions don't shift and the prompt cache still hits — and the tags stay hidden unless a later phase deliberately surfaces them. This is *why* the schema change is behaviour-neutral. **Part 3 extends this to names/aliases:** `_dedup_aliases` is the `Alias` twin of `_dedup_details` (collapse same-`text`, union sources); `_combine_group` now carries each losing member name into the `Alias` it becomes (with that member's `name_sources`) and stamps the merged `name_sources` via **`_canonical_sources`** — the winning canonical's provenance, derivable because `_validate_decision` forbids an invented canonical and `_resolve_canonical` snaps it to a verbatim member string (a **case-sensitive** match on purpose, so a differently-cased twin's sources don't bleed in); and `_entity_for_prompt` now also reduces `aliases` to bare text and drops `name_sources`, so the merge prompt's SHAPE stays byte-identical (aliases were already bare strings pre-Part-3), keeping merge decisions + the prompt cache put. Then deduping `Quote`s on the full **(text, speaker, source_file)** triple (two different speakers attesting the same fact both survive — that's *more* evidence). Because Python physically can't paraphrase a string it's appending to a list, **rewriting a fact is impossible by construction**, the same reason as the extractors' LLM-reasons / `_build_entry`-assembles shape, one layer up. `len(entries) < 2` short-circuits with **no API call**. **Conservative posture:** a false merge fabricates a Frankenstein entity (the sin avoided); a false split is just a harmless duplicate page caught on review — so merge **only on strong evidence** (a stated alias, or one name already in another's `aliases`), and murky pairs go to `possible_duplicates` (a findable `[REVIEW]` log line, **not** merged). **Typo handling:** spelling-closeness is a *trigger to investigate*, never a decider — one edit separates **both** "Maltaav"/"Maltraav" (a real typo → merge) **and** "CJ"/"DJ" (siblings → don't), so context decides; a **short-name rule** (names ≤ `SHORT_NAME_LEN`=3 chars, e.g. initials) is **stated-alias-only**, enforced both in the prompt and by a pure-Python `_short_name_veto` (it fires only when a short name is in play, and errs toward veto since over-blocking just yields a duplicate page). **Scalar resolution (pure Python, after the LLM parse):** `is_pc` → True wins (False = absence of evidence; quiet `debug` log); `scope` → broadest wins via `_resolve_scope` (matches History's default-to-`world` philosophy — a too-broad event is loud and gets corrected, a too-narrow one hides; quiet `debug` log); `date_text` (HistoryEvent only) → a stated date beats `None` via `_resolve_date_text`, and on a **clash** (two merged events stating *different* dates) it keeps the first and logs quietly at `debug` — non-destructive, since the other date still survives verbatim in the merged event's quotes/description — so merging duplicate events never silently drops a stated date; `player_name` → resolved by `_resolve_player_name(members, allow_majority=…)`: on the deterministic **identical-name floor** any clash still **vetoes** (`_VetoMerge`, caught by the apply loop → entries kept separate + a loud `[REVIEW]`), but on the LLM's **evidence-based merges** a strict **plurality wins** (loudly flagged; only a true tie vetoes), since the LLM grouping two records with different `player_name`s is far likelier one mislabeled record than a genuine two-PC collision; `chronological_position` stays **untouched (`None`)** at 4.1a — the 4.1b timeline pass fills it. **Contradiction handling:** a genuine semantic disagreement between two merged details (`DetailConflict`) becomes a **rich, findable `[REVIEW]` log line** (entity name, both detail texts, both sources, the LLM's note) that Phase 5.3 funnels into `review.txt`; **both** details are kept and there is **no model field** for it. The `[REVIEW]` prefix marks every loud human-actionable flag; the quiet auto-resolved `is_pc`/`scope` clashes deliberately log at `debug` and stay out of the review queue. **Error handling:** the `ReconcileDecision` is Pydantic-validated *and* run through a `_validate_decision` sanity pass (every index in range; no index reused across two groups; **every merge group has ≥2 members** — an empty/one-entry "merge" is malformed and would otherwise crash the combiner's `members[0]`, so it's rejected here and re-guarded by a skip in `_apply`; each `canonical` is genuinely a name/alias of one of its members — so even the heading can't be invented) — any problem is treated like bad JSON and **retried up to 3×**; total failure returns the entries **unmerged** with a loud `error` (under-merge is the safe direction). Parsing is tolerant on purpose: `_parse_decision` tries the fence-stripped text first, then falls back to `_extract_json_object` (a brace-balanced, string-aware scan) so a Sonnet reply wrapped in a conversational preamble — which `strip_code_fences` can't peel — still yields the embedded object instead of burning all three retries on a parse error. And because the validator matches `canonical` case-/whitespace-insensitively, the combiner **snaps it back to the verbatim member name/alias** (`_resolve_canonical`, preferring a name over an alias) before using it as the heading — otherwise a recased "lake mundi" would become the page title and demote the real "Lake Mundi" into the aliases. **The "cross-reference index" originally floated for 4.1a was dropped** — nothing downstream consumes it (the 4.3 cross-link pass builds its own slug map and blind-scans the text; no renderer reads a backlinks structure); if a "See also" feature ever lands it'll be added later as pure Python. **Phase 4.1b (the timeline-ordering pass) is complete** — built in two parts (the pure-Python *engine* and the *LLM layer*), both living in `reconciler.py`; `Reconciler.order_history(events)` is the entry point the Phase 4.5 orchestrator calls on the deduplicated `HistoryEvent`s after `reconcile()`. It runs **after** the 4.1a merge, over the deduplicated `HistoryEvent`s, and fills their two timeline fields (`calendar_system` + `chronological_position`). **Model:** a sorted **spine of dated events** with **gaps** between them, into which relative (undated) events get woven. A date is a **tuple of parts, biggest unit first** (`[1347]` for "1347", `[4, 200]` for "4th Era 200"), so `_build_spine_and_gaps` tuple-sorts element-by-element with **no calendar arithmetic** — and **Python owns every `chronological_position`; the LLM never emits one** (the contracts `DateDecision`/`DatedEvent` + `PlacementDecision`/`GapPlacement` in `models/reconcile.py` carry only indices, system labels, sortable `parts`, and gap IDs). Same-date events **collapse into one rank-group** (a tie → no phantom gap, and "after Founding"/"after Charter" point at the *same* gap; tied markers still get adjacent positions). **The `(undated)` pseudo-system** (`UNDATED` constant) is always present — a single gap for relatively-ordered date-less events, which get `calendar_system=None`; a fully-dateless campaign is just the case where it's the *only* system (**same code path**, zero markers → one gap). That gives the renderer (4.4) a clean **three-way read**: `calendar_system`+position set → a dated timeline; `None`+position set → the undated-but-ordered timeline; `None`+position `None` → **Could Not Place**. **Gap IDs** (`"AR years#1"`, via `_gap_id`) are **opaque keys** matched by exact string against a lookup dict, never parsed back apart — so a label with a `#`/space can't break them, and a stray/hallucinated gap ref just falls to Could Not Place. `_weave_and_stamp` walks each system's spine, drops placed relatives into their gaps in order, stamps `chronological_position = 0,1,2,…` **per system** (each timeline numbers from zero; the renderer sorts within each separately), and returns **new events via `model_copy` — never mutating the inputs**. **Two guard layers:** `_sanity_guard_parts` is best-effort — it rejects a `parts` tuple sharing **no digit** with a date that *has* digits (catching `[343]` for "342 AR"), but **trusts a word-only date** ("the Third Age") since pure Python can't parse calendar notation, with the verbatim `date_text` as the human safety net and a slip being at worst a minor mis-sort, never lost/fabricated lore; and the structural validators `_validate_date_decision` / `_validate_placement_decision` (index range, duplicate index/gap, an event with no `date_text`, non-positive/empty `parts`, an empty system label, an unknown gap, double-placement, or a *dated* event the LLM tried to re-place by gap) which **Brief B retries on**, like 4.1a. The split is deliberate: a *guard* failure drops a single event to relative placement without failing the call; a *validation* failure retries the whole call. **The LLM layer (`order_history`)** wires **two `call_claude` calls** onto that engine: Call 1 (`DATE_EXTRACTION_PROMPT`) reads each dated event into a `system` label + sortable `parts` tuple → a `DateDecision`; Python sorts it (`_build_spine_and_gaps`); Call 2 (`PLACEMENT_PROMPT`) drops the undated events into gaps by ID → a `PlacementDecision`; Python weaves + stamps. **The LLM emits sort keys and gap choices, never positions.** **Call 1 is skipped entirely** when no event has a `date_text` (a fully-dateless campaign makes a single placement call), and **Call 2 is skipped** when nothing is undated. **Graceful degradation, because `_weave_and_stamp` always runs:** a failed Call 1 → empty spine → events ordered relatively or Could Not Place; a failed Call 2 → the dated spine still stamps, only relatives → Could Not Place; a `_sanity_guard_parts` failure on one event drops *just that event* to relative placement (loud `[REVIEW]` log). A total LLM failure yields a *less-ordered*, never *corrupted*, timeline. **Same plumbing as 4.1a**, now run twice: the tolerant fence/preamble JSON parse (`_parse_json_model`, generalizing `_parse_decision` to any model) and the parse → validate → retry-3× → safe-fallback loop, exercised by the `FakeClient` harness. The **system labels are the LLM's job too** — it uses a *consistent label per calendar* and merges interchangeable notations ("1347" / "Third Era 347") into one system **only when the text states the equivalence**, never via real-world calendar knowledge. **Post-4.1 the reconciler grew a large deterministic-floor + arbiter layer (drift):** BEFORE the LLM call it runs pure-Python merges — `_merge_identical_names` (same `name_key`, from `text_norm`), `_merge_article_variants` ("the Citadel"/"Citadel"), `_merge_unique_subset_names` (collapses a name-fragment into its UNIQUE containing entity, e.g. "Mundi"→"Lake Mundi" — uniqueness-gated so a fragment that is a subset of 0 or ≥2 entities is skipped, `[REVIEW]`-logged, under-merge-safe, runs after `_merge_article_variants`), and `_merge_declared_characters` (folds the name fragments the declared party groups under one player, matched on the recognition cross-product from `player_map`, with exact/typo/token folds + declared-pronoun stamping + player-real-name alias stripping; it deliberately does NOT gate on `is_pc`/`player_name`, so a coincidental NPC sharing a player's first name can fold in — an accepted user trade-off, softened by a loud `[REVIEW]` and an EXPLICIT-contrary-`player_name` veto). `_candidate_pairs` surfaces suspicious-but-unmerged pairs to the LLM as an ADVISORY in the USER message only (the system prompt stays byte-identical for cache stability). Overlapping merge groups are coalesced (`_coalesce_overlapping_groups`, capped `MERGE_COMPONENT_CAP=8`) with per-subset salvage on a rejected group. `Reconciler.__init__` now takes `player_map=` (threaded from the orchestrator) for that floor. **`order_history(events, current_year=None)`** gained reference-year anchoring — a present-relative date ("200 years ago") resolves against `current_year` (from `--current-year` or auto-detected) via `DatedEvent.anchor_relative` + `DateDecision.reference_year/reference_system`. **`resolve_cross_type(by_type)`** is a NEW final dedup pass: one real entity captured under several types (a people also extracted as a Location) goes to an LLM arbiter (`CrossTypeDecision`/`TypeChoice` in `models/reconcile.py`) that picks the correct type(s), folds the losers' facts into the winner, and drops the wrong-type pages — leaving a legit Location+Organization dual (a realm) intact; degrades to a no-op on failure. **`flag_subject_bleed(characters)`** is a log-only `[REVIEW]` pass flagging a character detail whose leading grammatical subject is a DIFFERENT character.
- `agents/prose_agent.py` (Phase C, NOT in earlier docs) — the post-reconcile **prose pass**, run by the orchestrator AFTER reconcile+timeline (and, for the restricted doc, after the exclusion carve — leak-safe like the History re-run) and BEFORE `render_wiki`. Two deliberately split layers. **(1) De-conflation is DETERMINISTIC** (pure Python, no LLM): `build_deconflation_map(characters)` builds `{player-name → character canonical name}` from the reconciled `Character`s (the only place the player↔character link lives), with TWO collision guards (drop a player name mapping to 2+ distinct characters, and drop one that collides with an in-world character name/alias — each a `[REVIEW]`); `deconflate_entities`/`deconflate_events` then word-boundary-replace those player tokens in every `details[].text`, `name`, and `aliases[].text` / event `description` + `name` (collapsing the now-redundant `"<Character>'s character"`) via `model_copy` — quotes + `name_sources` stay verbatim. Running it BEFORE the LLM is the anti-swap fix: the copyeditor never sees a player name. **(2) `ProseAgent(BaseAgent)` is a CONSTRAINED COPYEDITOR** (inherits `BaseAgent` directly like the reconciler; PROSE role → Sonnet @ 0.2; `batch_size=12`): `polish_entities`/`polish_events` set the new **`prose`** field via `model_copy` — it may ONLY merge duplicate restatements, smooth flow, fix punctuation, and (for a declared `Character`) enforce declared pronouns; it must NOT infer, add, reassign, or invent a relationship or swap a subject (the old free rewrite inverted subjects from terse first-person facts). No verbatim check (a copyedit is a reword — the verbatim quotes ride UNCHANGED into the footnotes as the audit trail); a per-item failure leaves `prose=None` and the renderer falls back to the already-de-conflated raw details. The orchestrator's `_apply_prose` degrades each stage independently.
- `renderer/` — pure-Python markdown generation (no LLM). `footnotes.py` (`FootnoteRegistry`, done, Phase 4.2) mints stable, deduplicated `[^N]` footnote numbers from `Quote` objects (dedup key = the `(text, speaker, source_file)` triple the reconciler dedups on, except the registry additionally whitespace-collapses the text via a shared `_normalize_quote_text` so internal newlines/tabs or stray edge spaces can't split one footnote — same field shape, stricter text match, not a byte-identical key) and renders the `## Footnotes` definitions block. It is **pure, no-I/O, no-log** — every input is an already-validated pydantic `Quote`, so there's nothing to police: `add(quote) -> int` is idempotent per distinct quote (an explicit `_next` counter, never `len()+1`, so a dedup-hit early-return can't reissue a number), and `render_definitions() -> str` returns the heading + `[^N]:` lines (each quote flattened to one line and wrapped in a **code span** so roleplay asterisks/underscores render literally) or `""` when empty (one emptiness check gates heading+body so 4.4 never peeks inside). Numbering is **render-order**, so rendering must stay single-threaded. The `[^N]` *insertion into prose* and document placement are 4.4's job; more renderer modules arrive in 4.4. `crosslink.py` (`slugify` / `build_crosslink_map` / `add_crosslinks`, done, Phase 4.3) is the **cross-link pass** — pure-Python, no-LLM, no-network (footnotes.py's sibling in the deterministic outer layer; all the expensive LLM work is cached upstream) — turning a bare entity name in already-rendered body prose ("Lake Mundi") into an internal link (`[Lake Mundi](#lake-mundi)`). Built and tested in **isolation**: `crosslink.py` was written before the renderer existed, so its tests run on **fabricated** markdown fixtures and it takes **no** dependency on `renderer/markdown.py` — the dependency runs the other way (`markdown.py` imports `crosslink`, now that Phase 4.4 is done). **Anti-hallucination ethos:** a wrong link is a quiet lie, so the bias is to **miss a legit link before ever manufacturing a wrong one** — matching is **exact** (modulo NFC + case + self-defined boundaries + the article rule) with **no** fuzzy/edit-distance/typo-tolerant matching anywhere (the prose scanned is the model's clean output; typos survive only in verbatim quotes, quarantined in the footnotes block). **`slugify(name)`** is the single source of truth for anchor ids — we **own our anchors** (4.4 stamps `<a id>` from the same table the linker reads, so they can't drift): NFKD ASCII-fold (drop combining marks, keep ASCII — "Théoden"→"theoden"), lowercase, spaces→hyphens, **keep internal hyphens** ("Half-Elf"→"half-elf") but **strip apostrophes** ("Mal'taav"→"maltaav"), collapse+trim; an all-punctuation name slugs to `""` and the **empty-slug fallback** (`entity-<N>` by stable index + `[REVIEW]`) lives in the **map**, not slugify (only the map has the index). NFKD already folds byte-variants, so slugify needs **no** NFC step — **NFC is applied only at the matching layer** (build-time surface forms + match-time prose), the one place two byte-identical strings must compare equal. **`build_crosslink_map(noun_entities, events=None, common_words=None)`** builds the **single source of truth once** over the **five noun types** (`Location`/`Character`/`Organization`/`Item`/`PeopleAndCultures` — each a link **target** *and* a **source** via its `name`+`aliases`) **plus the history events (4.4)**: an **eligible** event — its article-stripped name isn't sentence-ish, judged by the **same `_looks_sentence_ish` gate** the entity source pool uses — is **both target and source** (it gets an anchor; its `name`+`aliases` join the pool), while a **sentence-shaped/gated-out** event (the extractor fallback-name case) stays **neither** (no anchor, not in the pool) — its `description` is still run through the walk at render time so noun mentions inside it light up. The asymmetry is deliberate — **entities always get an anchor** regardless of the gate; **events must clear the gate to earn one** — and events are anchored **after** the entities against the shared `used_anchors` set, so an event-vs-entity slug clash leaves the entity the clean slug (`riverton`) and suffixes the event (`riverton-2`): the "entities before events" tiebreak, which falls out of pass order with no explicit type-ranking, and from there an anchored event is **just another claimant** — Passes 3–4 resolve event-vs-entity and event-vs-event clashes uniformly, unchanged. The returned `CrosslinkMap` (a frozen dataclass) exposes `anchors` (name→final anchor, **entity-only** — events never enter it), a parallel `entity_anchors` (authoritative per-entity — correct even when two entities share a name), **`event_anchors`** (parallel to the events passed in: the event's anchor, or `None` where it was gated out — the renderer stamps nothing there; an empty-slug event falls back to `event-<N>`, which can't collide with an `entity-<N>` fallback), the longest-first `sources` pool of `(surface, anchor)` pairs, the compiled `pattern`, and a private `_lookup` (surface→`(anchor, article_required)`). **Every messy case is resolved here, once, never during the walk:** slug collisions (two different entities slugging the same → suffix `riverton`, `riverton-2`, … + `[REVIEW]`; a realm that's both a Location and an Organization thus gets two suffixed anchors and its shared surface drops out as ambiguous); alias-collides-with-a-real-name (real name wins, alias dropped + `[REVIEW]`); same alias on two entities (can't pick → out of pool + `[REVIEW]`); a **source-eligibility gate** that holds **sentence-ish** surfaces (>6 words, or internal `.!?;:`) out of the **source** pool — they keep their anchor as a **target** — to defang extractor fallback names by design; and a **common-word gate** from `config/crosslink_words.json` (`{"require_article": [], "never_link": []}`, **both default empty** so a fresh clone runs clean) where `require_article` words fire only with a leading "the" and `never_link` words are held fully out, both matched against the **article-stripped** surface form (so the config lists bare words). Names and aliases share **one** pool sorted longest-first **together** (an alias can outrun another entity's whole name — "The Brotherhood of the Phoenix Blood" vs. a bare "Krieger"). A separate tolerant `load_crosslink_words` (missing file → both empty) is the orchestrator's to call and thread in, like the speaker map — `build_crosslink_map` itself does **no** file I/O. **Phase 4.5 hardened the loader:** a missing file still returns empty defaults, but a file that *parses yet is the wrong shape* now **raises** — a non-dict, or an unrecognized/typo'd key like `"neverlink"` (which would otherwise fall through `.get()` to an empty default and silently disable the config). Per-value type checks (asserting each list is a list) are deliberately NOT added — guards come from real failures, not speculatively. **`add_crosslinks(block, crosslink_map, this_anchor)`** runs the weave over **one** block (an entity page, or a single event description). A **no-go pre-pass** tapes off ATX headings, fenced code blocks, inline code spans, and existing `[text](url)` links (footnote `[^N]` markers are inert and need no handling); the block is **NFC'd once up front** so no-go detection and matching share stable indices. Matching is **one left-to-right pass of a single longest-first regex via `re.finditer`** — non-overlapping, which makes **re-linking your own output structurally impossible** (no manual cursor, no sequential `str.replace`). Matches are **case-sensitive**, use **self-defined word boundaries** (apostrophe/hyphen are word-internal, so bare "Mal" never fires inside "Mal'taav" and "Riverton" never inside "Rivertown"/"preRiverton" — a plain `\b` would mis-split), and the **article rule** (a leading "the"/"The" is **never** part of the link — always emitted outside the brackets with its original casing; only whether it's *required* to fire changes by surface type — a proper noun fires with or without, a `require_article` common word only with "the"). **First-occurrence + self-suppression are one rule:** a per-block `seen` set of **anchor ids**, pre-seeded with `this_anchor`, so a second mention of an entity stays plain *and* the page never links to itself (keyed on the **target anchor**, so an alias resolving to the page's own anchor is suppressed too); `seen` resets per block. Tests are `tests/test_crosslink.py` (fabricated fixtures, every brief case + additive hardening for NFC byte-variant *matching*, the left word boundary, and lowercase-only prose isolated from the `seen` rule — the last two added after an adversarial review found the originals could pass a wrong-link regression). **Deferred to the rest of 4.4:** *stamping* the event anchors into rendered output as navigable timeline anchors (the pool-promotion + anchor-minting half of the old `[DESIGN]` item landed with the `events` param above; the navigable half needs 4.4's timeline rendering), a "see also"/backlinks structure, and Wikipedia-style bolding of suppressed self-mentions. `markdown.py` (done, Phase 4.4) is the pure-Python **markdown layer** (no LLM, no I/O). Its timeline half is `render_history` + two private helpers (`_event_bullet`, `_bullets`). **`render_history(events, cmap, registry) -> str`** renders the History/Timeline section from the **woven** events (each already stamped by 4.1b with `calendar_system` + `chronological_position`). The **load-bearing contract:** `events` MUST be the **same list, same order** passed to `build_crosslink_map`, because `cmap.event_anchors` is parallel to it by index — so the function **pairs each event with its anchor into `(event, anchor, original_index)` rows BEFORE any sort** and only ever sorts/moves those rows; looking up `event_anchors[i]` by a post-sort position would silently attach every anchor to the wrong event (the same falsy-`0` class of trap, and there's a dedicated footgun test that fails against that naive impl). **Three buckets, read off the two stamped fields with `is not None`/`is None` — never truthiness (position `0` is a real first event):** `calendar_system is not None` → that system's **dated timeline**; `None` system + position `is not None` → **Undated Events** (order known, date not); `None` + `None` → **Could Not Place** (no order). **Header:** `## History` by default, `## Timeline` in **exactly one** case (no dated systems *but* ≥1 ordered undated event forms a real sequence); could-not-place-only stays `## History` (no sequence to name) with an explanatory note. **Two notes, both labelled `**Important Note:**`** (they never co-occur): the **multi-system** note (2+ systems, warns systems can't be cross-compared) and the **could-not-place-only** note (no dated/undated content, says the list is alphabetical not chronological) — the latter *replaces* the `### Could Not Place` subhead (a subhead with nothing above it to separate from is dropped, same reason `### Undated Events` vanishes in the all-undated body). **Subheads appear only when there's content above them:** `### {System}` only with **2+** systems (one system's entries go straight under `## History`), `### Undated Events` only when dated content precedes it (never in the `## Timeline` case), `### Could Not Place` whenever other content precedes it. **Sorts:** dated *sections* by event-count **desc** then system name (a stable property of the system); within dated/undated by `chronological_position` asc (the weave numbers `0,1,2,…` per spine → already a total order, no tiebreak); Could Not Place **alphabetically by name** (deterministic *and* honestly non-sequential, so a reader can't misread it as chronological), original index the final tiebreak. **Entry atom is name-forward** — `- <a id="…"></a>**Name** — date. description[^N]…` — with the **anchor conditional** (stamped only when the event earned one; `None` → no `<a id>`, still renders) and the **`— date` tag conditional** (present only when `date_text` is truthy, the one place truthiness is the right check so `""` hides like `None`). The event's **`description` is the only part run through `add_crosslinks`** (with the event's own anchor as `this_anchor`, so a self-mention doesn't link back), never the bold name or date; supporting-quote footnote markers append at the description's end (a history event is one description block — no per-fact hang points, that's an entity thing). Returns `""` when there are no events, so the caller can drop the whole section without peeking (same emptiness contract as the footnote registry). With `render_history` (Brief 2), **Phase 4.4 is complete**: `markdown.py` now also holds the **five entity renderers** (`render_locations` / `render_characters` / `render_organizations` / `render_items` / `render_people`) and the top-level **`render_wiki`**. **Entity rendering** is uniform across all five types via two shared helpers (`_render_entity` + `_render_entity_section`), the named functions being thin label-passing wrappers: each entity is a `### {Name}` heading with its `<a id>` stamped **inline** (entities are **never gated out** — they always get an anchor, unlike events), followed by a prose body (its `details` joined into **one** paragraph, run through `add_crosslinks` as a **single block** with the entity's own anchor as `this_anchor` so a self-mention doesn't link back) and footnote markers at the **end** — never per-fact, because `details` and `supporting_quotes` have **no index-to-index mapping** (the quote list is deduped at extraction), so the quotes back the **whole entity** and their markers land at the end, the *same* end-of-block footnote shape as an event (entities reuse that shape rather than inventing a per-fact scheme). `Character.is_pc` / `player_name` are **stored but not rendered yet** (like `HistoryEvent.scope`). Entities sort **alphabetically by name** within a section (anchor the tiebreak); an empty section renders `""` and is dropped (never a bare header). **`render_wiki(locations, characters, events, organizations, items, people, common_words=None) -> str`** is the top-level assembly and the seam **`main.py`** plugs into (it takes the six typed lists explicitly): it builds the cross-link map **once** over all entities + events (concatenating the five entity lists — the concat order only decides which side keeps the clean slug on a cross-type name clash, cosmetic), then **pairs every entity with its anchor and splits the pairs back apart by `isinstance`** (an object's type can't drift; length arithmetic can), so an anchor can never desync from its entity through the type-split or a section sort. It shares **one** `FootnoteRegistry` across every section and renders the six in the **fixed order Locations → History → People & Cultures → Organizations → Characters → Items** — *also* the footnote-numbering order, so numbers climb down the page — appending the footnote-definitions block **last** and dropping empty sections; returns `""` for a completely empty world. Tests are `tests/test_markdown.py` (offline — `render_history`/`render_wiki` and `build_crosslink_map` are all pure — no key, no `integration` marker). **Post-4.4 renderer additions (drift):** the entity body now prefers the **`prose`** field (Phase C) over the joined `details`, falling back to the join when `prose` is `None`; display names run through **`_normalize_display_name`** (Title-Cases screaming ALL-CAPS, preserves ≥4-char acronyms) and details join via **`_smart_join_details`** (terminal periods); **`slugify` now delegates to `text_norm.slug`** so anchors and reconciler merge-keys can't drift; section/entity sorting uses **`_alpha_key`** (article-ignoring); empty entities are pruned by **`_is_renderable`**; the footnote code-span fence sizes dynamically; and the crosslink pass gained a **case-insensitive bucket-F match** (`_is_case_safe`/`_ci_lookup`) plus **`_dual_canonical_anchor`**, which keeps a Location+Organization shared-name realm linkable (routed to the Location anchor) instead of dropping it as ambiguous. **Known open gap:** display names are Title-Cased but still NOT markdown-escaped, so a name containing `*` `_` `[` or a backtick corrupts its bold/heading.
- `orchestrator.py` (top-level) — `Orchestrator` + `PipelineConfig` (done, Phase 4.5). The **traffic cop** that ties every existing stage into one ingest-to-wiki flow; it does **no LLM work of its own** — its whole job is sequencing, the extractor fan-out, and the error policy. `Orchestrator(client=None, cache=False)` resolves each agent's backend **per role** via `LLMBackendResolver` (see the `agents/llm_client.py` note): with no env set — or an injected fake `client`, which overrides ALL roles for tests — every role gets one shared Anthropic client + its default model (NOISE→Haiku, EXTRACT+PROSE→Sonnet, RECONCILE→**Opus**); a `WIKITIZER_<ROLE>_MODEL` prefix routes just that role to an OpenAI-compat model. `_build_agents` (its own method so a test can subclass and swap in stub agents — no network, no key) threads the characters extractor's **required `player_names`** (`config.speaker_map.values()`, the anti-conflation roster) AND `player_map`, passes `player_map` to the reconciler (its declared-merge floor), builds the `ProseAgent`, and forwards `cache=self.cache` (the `--cache` dev disk cache). `run(files, config, exclude_sources=None) -> WikiOutput` walks: **parse each file → concat in pass-order** (pure Python, no LLM; a parse failure is left to **RAISE/abort** since it's pre-any-paid-call and skipping a requested file means silently-missing lore) **→ noise-filter → `select_for_extraction` → six extractors in a `ThreadPoolExecutor`** (`config.max_workers`, default 6; threads because each extractor is network-bound and they share only the thread-safe client) **→ `reconcile` per type (ALSO fanned over a `ThreadPoolExecutor` — each per-type call is independent) → `resolve_cross_type` (cross-type dedup) → `flag_subject_bleed` (log-only) → `order_history(current_year=…)` → prose (`_apply_prose`: deterministic de-conflation, then the LLM copyedit) → `render_wiki`** (called with the *final* events list; render_wiki builds the cross-link map internally, so the "same list, same order" contract is handled in there). **Error policy — degrade toward less-complete, never corrupt (the `_weave_and_stamp` spirit):** the **extractor**, **per-type reconcile**, **cross-type resolution**, **`order_history`**, and **both prose stages** each **degrade** — log a loud `[REVIEW]` line and substitute a safe fallback (`[]` for a dead extractor's section / the **un-reconciled** list on a reconcile failure / the **unordered** events → "Could Not Place" on an `order_history` failure) — while the **noise filter is the sole hard-stop** (a dead funnel would otherwise dump the whole *unfiltered* chat onto six Sonnet extractors, ~6×-ing the bill on an already-broken run): it logs at `error` and **re-raises**, with **no `[REVIEW]` prefix** because a crash is unmissable on its own. `PipelineConfig` (a dataclass: `speaker_map`, `crosslink_words`, `max_workers=6`, **`current_year: Optional[int]`** for the timeline's present-relative dates, and **`player_map`**, the declared party) is loaded **once by `main.py`** as plain dicts (not paths) so the orchestrator does zero config I/O and tests build one inline with nothing on disk. `run` returns a **`WikiOutput(full, restricted, characters)`** — `characters` is the reconciled PC list (post-merge names/aliases) surfaced for `--confirm-players`; the restricted doc's prose runs on the POST-carve entities (leak-safe by construction, like the History re-run via `_history_pipeline`). Tests are `tests/test_orchestrator.py` (offline — stub agents via a `_build_agents` override + a `monkeypatch` of the pure `parse_messages` function; covers the happy path, each degrade path, the hard-stop, empty input, the full fan-out, and shared-client wiring, plus one additive real-log-file test that locks down the real `parse_messages` arg order). **Phase 4.6 Part 2 added the exclusion mechanism (two docs from one run):** `run` now takes `exclude_sources=None` and returns a **`WikiOutput`** dataclass (`full` always; `restricted` set only when exclusions were asked for, else `None` — distinct from `""`, which would mean "asked, but every scrap of content was in an excluded file, so nothing public survived"). It **validates the exclude names up front** (fail-fast at the very top of `run`, before any parse or paid call — a name matching nothing would silently leave those messages in the "restricted" doc, the exact leak this prevents), then, when exclusions are requested, builds a second **restricted** wiki: entities **carved** by `filter_entities` (confidential-only facts/quotes stripped from the already-finished lore — **no re-extraction**, reusing Part 1's `source_files` tags), and History **re-run** via the module-level `_history_pipeline` over the messages minus the excluded files — **leak-proof by construction**, since the History extractor never sees the secret messages, so a secret can't be woven into a description in the first place (there's nothing to filter after the fact). The **main run's History path is unchanged** — `_history_pipeline` is only the restricted second pass, run with the same degrade-don't-crash policy; `render_wiki` is **untouched** (it builds a fresh cross-link map + footnote registry per call, so the two docs are independent and the restricted doc's footnotes number from 1 on their own). `exclusion.py` (top-level, next to `orchestrator.py`) holds the two pure, LLM-free jobs: `validate_exclusions` (hard-fails if an excluded name isn't one of the input files; matches on the **bare filename**, since that's what every `source_file` stores — the parser sets `source_file = Path(filepath).name` — so the exclude list must be bare names like `"dm.txt"`, NOT paths, and even a path to a real input is a strict error with a "use the bare name" hint) and `filter_entities` (`_filter_entity` keeps a `Detail` if **any** of its `source_files` is not excluded, keeps a `Quote` whose `source_file` isn't excluded, and drops an entity left with **neither** a surviving detail nor quote — a source-less `Detail` is dropped since it can't be proven public, over-hiding being the safe direction for a secrecy feature; it builds new objects via `model_copy` and never mutates the originals the full doc still needs). History is **not** filtered in `exclusion.py` — the orchestrator re-runs it instead. **Phase 4.6 Part 3 CLOSED the entity-name leak** an earlier review found: names and aliases now carry provenance (`name_sources` on each entity + the new `Alias` model's `source_files`), tagged at extraction from **file-pure batches** — `BaseExtractor.extract` groups messages by `source_file` before chunking, so ONE file owns every name/alias/fact/quote in a batch (load-bearing: a mixed batch would let Claude cite a public quote while weaving in a secret fact, silently defeating the feature). So `filter_entities` now also strips secret-only aliases and, when the canonical `name` isn't provably public, **re-heads** the entity to its first surviving public alias (old secret name dropped, not demoted; if no public alias survives — which a file-pure batch makes impossible for a surviving entity — it drops the entity + logs `[REVIEW]`). The restricted doc is now leak-safe for **facts, quotes, aliases, names, and all of History** — still one extraction, one reconcile, zero extra LLM calls, both docs from the same reconciled objects. Not behaviour-neutral for the FULL doc: its extraction output shifted once when batch boundaries became file-pure (a one-time drift, not a leak). The merge prompt's SHAPE is unchanged, because `_entity_for_prompt` also reduces aliases to bare text and drops `name_sources`.
- `main.py` (top-level) — pipeline entry point (done, Phase 4.5, runnable). Sets up logging (`logging.basicConfig` at INFO — Python logging is silent until configured, so without it every `[REVIEW]` flag would go nowhere), calls `load_dotenv()` so the Anthropic SDK finds `ANTHROPIC_API_KEY` (a `.env` is NOT auto-loaded, and key-loading belongs here, not in `base.py`), loads the config files up front into a `PipelineConfig` (`load_speaker_map` + `load_crosslink_words` + **`load_player_map`** — a missing/malformed config raises **here**, before any paid call, which is the point), builds the `Orchestrator`, and — via an **`argparse` CLI (Phase 4.6 Part 4)** — runs it over the given files and writes the result(s) to disk (utf-8; `output/` is gitignored — a real-log wiki carries PII). `parse_args(argv=None)` and `main(argv=None)` take `argv` explicitly so tests drive them without touching `sys.argv`. The three args: **`--files`** (required, `nargs="+"`, no default — the old `FILES` pointed at gitignored logs, so a default would confuse a fresh clone; a **named** arg, not positional, to dodge the `nargs="+"` positional-vs-optional ambiguity next to `--exclude-sources` and keep the two filename lists distinct), **`--output`** (default `output/wiki.md`), and **`--exclude-sources`** (`nargs="+"`, default `[]`; the flag with **no values** is an error, omitting it means no restricted doc). The restricted path is **derived** from `--output` by `restricted_path()` (`output/wiki.md` → `output/wiki_restricted.md`, exactly Part 2's old `RESTRICTED_OUTPUT_PATH` — so default behaviour is unchanged — using **`with_name`, not `with_stem`** for the 3.9.6 pin), so both docs always land together wherever `--output` points rather than the restricted one having its own arg. **Beyond those three, the CLI grew six more args (drift):** `--speaker-map`/`--player-map` (paths, defaulting to the `SPEAKER_MAP_PATH`/`PLAYER_MAP_PATH` module constants — so those are now overridable, not "not CLI args"), `--current-year YEAR` (the timeline's present-day anchor for relative dates), `--cache` (turn on the dev disk cache), `--confirm-players` (after the run, interactively confirm/save who plays each discovered PC to `config/player_map.json` via `confirm_player_map`, applied on the NEXT run), and `--no-player-map` (opt out of the **required** declared party — `main` hard-stops with a `SystemExit` before any paid call if no party is found and this flag is absent, since PC disambiguation depends on it). It writes `output.full` to `--output` and, only when `output.restricted is not None`, the derived restricted doc (an *empty* restricted string is still written, with a warning, since "every source was excluded" is a real answer). The CLI does **not** re-validate the exclude names — `validate_exclusions` stays in `run()` so **every** caller inherits the guard; a bad `--exclude-sources` name (or a path instead of a bare filename) raises `ValueError` from inside `run()` **before any paid call**, with the helpful "use the bare filename" hint. `CROSSLINK_WORDS_PATH` stays a module constant (no CLI override); `SPEAKER_MAP_PATH` / `PLAYER_MAP_PATH` are now the *defaults* for `--speaker-map` / `--player-map`. **Phase 4.6 is complete** — `--exclude-sources` works end-to-end (mechanism *and* CLI). Tests are `tests/test_main.py` (offline — see Testing conventions).

## Chat log format
The pipeline ingests **imessage-exporter TXT exports ONLY** (`imessage-exporter -f txt ...`; parsed by `parsers/imessage_export_parser.py`). Each message is a two-line **handshake**: a timestamp line (`May 17, 2022  5:29:42 PM`, the message boundary), then a sender line (`Me` = the exporter → the `"exporter"` speaker-map key; else a resolved contact name or a phone handle), then one or more body lines, then a blank line. Read receipts are appended to the timestamp line in parens; reactions (`Tapbacks:`), attachment paths, replies, and group announcements are **structurally** annotated and stripped in the parser, so there is nothing reaction-shaped to post-filter. Senders resolve through the speaker map (`_normalize_phone` matches E.164 keys); an unmapped handle passes through as-is. (The old copy-paste "legacy" parser + its `--input-format` flag were removed — imessage-exporter is the single committed format.)

## Testing conventions
Use pytest's `tmp_path` fixture to write throwaway config/log files rather than touching real ones. Test that bad input raises the right error with `pytest.raises(...)`. `tests/test_main.py` (the CLI, Phase 4.6 Part 4) is **offline**: `parse_args`/`restricted_path` are pure, and the `main()` tests stub `Orchestrator`, `load_dotenv`, and both config loaders (the real `config/speaker_map.json` is gitignored, so an unstubbed `main()` would `FileNotFoundError` on a fresh clone).

Live/API tests (Phase 3.10: the six extractors against real Claude) are marked `@pytest.mark.integration`, **deselected by default** (`pytest.ini` sets `addopts = -m "not integration"`, so plain `pytest` never spends credits) and opted into with `pytest -m integration`. They `skipif` themselves when `ANTHROPIC_API_KEY` is absent — and the repo-root `conftest.py` calls `load_dotenv()` so a key in `.env` is loaded *before* that skip check runs (no false skip). Their assertions are deliberately loose (name/alias substring membership, counts, scope, emptiness — not exact strings) because LLM output isn't deterministic; the fact-vs-quote faithfulness check is manual, via the per-extractor eyeball reports each run writes to `tests/output/`. Fixture messages split by privacy: a **committed** synthetic module (`tests/fixtures/synthetic_messages.py`, fabricated boundary cases, runnable by anyone with a key) and a **gitignored** real-chat module (`tests/fixtures/real_messages.py`, the group's private campaign — same principle as `logs/`); the live suite imports the real cases in a `try/except ImportError` so a fresh clone runs just the synthetic subset. `tests/output/` is gitignored too. The shared `Case` dataclass + `Message` builder live in the committed `tests/fixtures/case.py`.

**Dev A/B evals (`evals/`).** `evals/` holds standalone dev A/B scripts that compare a candidate model against the trusted baseline over **real, gitignored** logs (real API spend, dev cache on) — e.g. `extract_ab.py` for the EXTRACT role, which runs the six extractors twice over the *same* filtered messages (Sonnet baseline vs. a cheaper candidate) and reports entity/quote coverage. They are **not** collected by pytest (the filenames don't match `test_*.py`, and `pytest.ini` has no `testpaths`/`norecursedirs` — pytest recurses `evals/` but collects nothing there) and they make real calls, so run them by hand (`python -m evals.extract_ab --logs logs/`).
